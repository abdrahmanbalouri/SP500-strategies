01 · Sources

Two jobs, separate datasets

Constituent prices

data/all_stocks_5yr.csv supplies daily open, high, low, close, volume, and ticker data. The current features use the date, closing price, and ticker; the remaining OHLCV fields support future extensions.

S&P 500 benchmark

data/sp500_index.csv supplies normalized index closes for performance comparison only. It does not train the model. The alternate HistoricalPrices.csv source needs its dates and whitespace-padded columns normalized before use.

Early rows have missing values because rolling indicators require price history. Median imputation belongs inside the model pipeline so every fold learns its fill values only from its own training observations.

04 · Target

Predict the direction of the tradable return

forward_return(D) = close(D + 2) / close(D + 1) − 1
target(D) = sign(forward_return(D))

Positive returns become class 1; negative returns become class 0. Flat returns and rows without a future price are excluded from fitting. The one-session gap allows a signal calculated after the close on day D to be acted on from day D + 1.

06 · Leakage controls

Rules that keep the evaluation honest

  • Sort records chronologically inside each ticker.
  • Calculate rolling indicators separately for every ticker.
  • Use only current and historical prices as model inputs.
  • Keep the post-2016 test period out of model selection.
  • Fit imputation, scaling, and the estimator inside each training fold.
  • Apply strategy weights to the same future-return horizon used by the target.
07 · Limitations

Checks before trusting results

Survivorship bias

Confirm that constituent membership reflects each historical date. A present-day list applied backward can overstate performance.

Corporate actions

Confirm whether prices are adjusted for splits and dividends, which can otherwise distort indicators and returns.

Missing values

The raw stock data contains a small number of missing cells. Inspect them before engineering OHLCV-based features.

Trading realism

Transaction costs, slippage, liquidity, and trading constraints must be handled by the backtest rather than this data pipeline.
